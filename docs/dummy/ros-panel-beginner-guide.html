ROS 面板操作指南

从终端启动，
在面板完成控制。

一个启动命令打开控制面板、RViz 和规划服务。面板负责管理本机 ROS 控制链，连接先进入只读；使能和运动由操作者另行确认。

1 加载当前环境

从桌面会话打开终端，输入 bash 后执行以下命令。将 ROS 仓库与 SDK 安装前缀改为本机实际位置。当前开发环境先加载 install_panel_guide，再加载包含最新控制包的 install_protocol，避免使用旧安装副本。

Bash · 复制后在终端运行 
# 在 ROS 仓库根目录打开终端；下面命令使用 bash
export ROS_WS="$HOME/kamin_work/00-code/dummy_ros2_consolidated"
export DPSDK_ROOT="$ROS_WS/../dpsdk"
# 填写与当前部署匹配的 SDK 安装前缀，不沿用旧日期目录
export DPSDK_HOST_SDK_PREFIX="/实际/SDK/安装目录"
cd "$ROS_WS"
source /opt/ros/jazzy/setup.bash
source install_panel_guide/local_setup.bash
source install_protocol/local_setup.bash
export ROS_DOMAIN_ID=83
ros2 pkg prefix dummy_bringup

应看到本机当前工作区的 dummy_bringup 安装路径。不要同时加载另一个旧工作区；无需重新编译或烧录即可使用已经安装好的面板。

部署端点必须明确填写

已有正确的 current/panel-config.json 时直接进入下一节，无需重复部署。换机、重新部署或更换实际USB端点时，命令行必须显式提供 --endpoint；缺少该参数会在创建部署前退出，不能沿用模板中的示例设备。

Bash · 复制后在终端运行 
# 将全部占位路径及设备标识替换为本机实际值；本命令只离线打包，不烧录或连接USB
ros2 run dummy_bringup deploy_manual_panel.py \
  --native "/实际/Native/dummy_joint_cli" \
  --firmware "/实际/固件.bin" \
  --identity "/实际/身份清单.json" \
  --endpoint 'serial//dev/serial/by-id/<设备标识>#baudrate=115200'

部署校验通过后才切换 current。实际设备标识留在本机配置与报告，不复制到公开文档。若长期停在 BOOTSTRAP_PENDING，先核当前部署端点是否仍是模板占位值及USB是否对应；反复重启面板不会修正错误的部署端点。还须核对设备在线报告的固件 SHA-256 与当前部署清单：烧录新固件后，应将经过验证的匹配固件、Native、身份和解码器重新部署到默认 current；仅在其他测试目录准备新部署，不会更新默认入口。身份不匹配时，USB虽能收到原始数据，ROS仍会拒绝接纳状态，标定按钮也会保持灰色；不要通过关闭身份检查或手改某个哈希恢复。已有控制链须先按第5节正常退出，再用新的部署启动。

2 启动唯一一份面板

Bash · 复制后在终端运行 
ros2 launch dummy_bringup manual_joint_panel.launch.py \
  backend:=ros \
  sdk_prefix:="$DPSDK_HOST_SDK_PREFIX" \
  config:="$HOME/.local/share/dummy_ros/manual_panel/current/panel-config.json" \
  moveit:=true \
  auto_calibrate_and_test:=false \
  operator_confirmed_double_limits:=false \
  report:="$ROS_WS/dummy_reports/manual-$(date +%Y%m%d-%H%M%S)"

启动后应看到六轴控制台和 RViz。报告目录由命令生成一个新名称，请勿提前创建最终目录，也不要重复使用旧目录。保留启动终端，后续可查看报错和正常退出。

启动确认框需要人工回答。只读查看或未证明真实双限位姿态时，选择“否”。只有机械臂确实已位于双限位，才选择“是”；这项确认不是自动使能或自动运动。不要为了消除提示而确认错误姿态。

连接目标统一为 真机-USB/ROS、真机-USB/Native、仿真-本地。Native 与 ROS 共用同一设备时，只能保留一个通信所有者；从面板切换目标，等待原链路释放。

软件模拟可将 backend:=ros 改为 backend:=simulator。需要真机 ROS 控制时仍须提供有效 SDK 与部署配置。启动失败先看终端，不要不断另开面板。

3 检查反馈，再恢复控制

先看实际角度、boot、reference 和只读连接状态。启动、重连本身不代表已使能；只有设备确认控制会话准备完成，执行按钮才会开放。

当前情况 操作
同一 REF 上电周期，reference 有效 点击“使能 / 恢复零点”，确认使用当前实际姿态。普通失能、关软件再连接无需重摆双限位。
REF 已重启或 reference 为 0 先支撑并人工摆到真实双限位；若本次启动确认选择了“否”，重新打开面板，在启动确认中选择“是”，再点击“双限位标定 / 恢复控制”，等待ROS标定并退到Rest后再测试。当前固件的RAM参考不能跨本次REF重启沿用。
电机单独重启、真实位置超限或反馈故障 先处理实际原因。不要通过反复清故障、重新采零来绕过异常。
重启后以本次反馈为准。REF重启后的只读连接可能为 reference=0，历史报告中的 ref1 不能复用。此时“重新连接”“双限位标定”“停止失能”可以使用，“使能 / 恢复零点”应禁用；本次只读启动确认选“否”，直接点击当前标定按钮只会提示“本次连接未确认双限位”，不会采零。正确顺序：支撑并摆到真实双限位 → 重新打开面板 → 启动确认选择“是” → 点击“双限位标定 / 恢复控制” → 等ROS标定并退到Rest，再检查新参考和反馈后测试。

在已有参考下恢复控制会以实际测量姿态建立 Hold，不要求先到 Home；Home、Rest 都是随后明确规划或执行的目标。

4 按页面选择运动方式

关节控制：“实际角度 → 目标”可复制当前测量角度，修改六轴目标后点击“执行六轴目标”。该路线直接通过 ROS 提交轨迹，检查限位和设备准入，不做 MoveIt 环境避碰；需要绕开圆柱等障碍时使用末端规划页。

末端规划：选择空间目标、Home 或工作 Rest，先规划并检查整条路径，再执行。透明目标/预览模型不是实际姿态；实际模型跟随测量反馈。新障碍、目标编辑和设备身份变化会作废旧规划，禁止复用旧路径。

自动测试：真机-USB/ROS下，恢复控制后在末端规划页点击“开始自动测试”。ROS默认时长为0＝不限时（手动结束）；填写正数可按总时长定时结束，不再有ROS特有的9.5分钟总时长限制。点击“结束并回 Home”停止增加目标，排空已检查尾段后回程；“立即中断测试”请求受控停车并保持当前使能，“停止并失能”用于释放控制。

持续测试与单次运行预算分开。

勾选“连续轨迹”后，每个运行段（RUN）内部平滑续接。随机轨迹窗口接近570秒时停止补充，沿设备已确认的尾段完成，收到正式Action完成及新鲜实际到位后，从实际姿态开始下一段；整轮测试继续，不会每段回Home。跨运行段会短暂停稳，不是无限长的无缝母轨迹。

单次轨迹的630秒预算、31500样本容量、许可检查、完整曲线碰撞检查及速度/加速度均保留。许可按本次运行段申请，不把整轮时长或“无穷大”传给设备；手动结束或定时时限仍作用于整轮。Native保留原有时长设置，本改动不调整Native控制路线。

自动测试中的短暂反馈等待。

同一GUI tick内处理长轨迹后，本地缓存可能刚跨过250ms，页面入口和后续路径身份检查之间也可能发生；这些缓存边界复用同一原期限等待，不把暂时失鲜误报成“规划内容改变”或立即触发Cancel。仅对已受理、同UUID和boot/reference/session的母轨迹，且许可、有效掩码、碰撞场景和控制图仍一致、缓存内真实CAN年龄满足原条件时，等待新的真实反馈；既有Action仍由ROS权威控制监督。

等待以最后真实接收锚加原2秒为界，并受原段截止约束，不能从“刚发现失鲜”重新计时。等待期间不新发或重发动作、不续期，也不凭旧位置确认完成；真正源反馈超龄、身份或许可等变化、原期限到期，仍按原逻辑停止。底层C++、SDK和REF的门限不变。

开发说明：Host长轨迹处理与本次修复范围

等待锚为 min(state_at, status_at, last_state_ns/1e9) + 2s，不越原段截止；见 AutoTest在途检查 与 _wait_for_ros_inflight_feedback。新鲜反馈恢复后，仍按原条件继续。

另行离线Host诊断的7461点构造、deepcopy和CDR合计约166–168ms，28500点约807–867ms；不是本轮硬链性能原件。Native会裁剪过去前缀，ROS处理完整母轨迹，Host工作量不同。本修复复用已有等待，不引入新线程或改协议。

此修复发生在C6六窗实采之后；原C6物理测量、冻结FAIL与另行批准的工程验收PASS保持原记录。软件回归与后续长时实机验收分别记录。

“结束并回 Home”排空已确认安全尾部后安排回程；“立即中断测试”中断当前测试，“停止并失能”用于退出控制。出现异常时保留日志，不强行执行回 Home。软件回归通过不等于本轮长时实机验收通过，应以当前实际测试结果判断。

5 退出、清理与重新启动

按“正常退出 → 检查残留 → 刷新发现缓存 → 手动重开”的顺序处理。以下命令在本页第1节已加载环境的 Bash 中运行，只处理本机这轮 Dummy 控制链。

5.1 优先正常退出

  1. 在面板点击“停止并失能”，等待设备确认释放，并检查新鲜反馈。
  2. 在最初启动面板的终端按 Ctrl+C，等待本轮 launch 退出。仅关闭面板窗口时，RViz 或模型发布进程可能仍然保留。
  3. 先完成下方检查，再打开新面板；不要同时启动两份机械臂通信所有者。

5.2 找不到原启动终端时

先查询本轮面板 launch，再向匹配的启动进程发送正常中断信号：

Bash · 复制后在终端运行 
pgrep -af '[r]os2 launch dummy_bringup manual_joint_panel.launch.py'
pkill -INT -f '[r]os2 launch dummy_bringup manual_joint_panel.launch.py'

SIGINT 与终端的 Ctrl+C 使用同一种中断信号。没有匹配进程时，pkill 可以无输出并返回1；继续检查残留，不要据此认定全部节点已停止。

启动进程已经退出，但还有模型、坐标、RViz 或规划节点时，查看实际进程。输出四列依次为 PID、父进程 PID、进程组 PGID、启动命令：

Bash · 复制后在终端运行 
ps -eo pid,ppid,pgid,args | grep -E \
  '[m]anual_joint_panel|[d]evice_action_gate|[m]ove_group|[r]obot_state_publisher|[s]tatic_transform_publisher|[r]viz2'

根据启动命令和进程归属，确认某个 PID 属于本轮残留后，再执行下面的交互命令。其他工作区也可能运行同名程序；不要沿用历史 PID。

Bash · 复制后在终端运行 
read -r -p '输入已核实属于本轮的残留 PID: ' DUMMY_ROS_PID
if [[ "$DUMMY_ROS_PID" =~ ^[1-9][0-9]*$ ]]; then
  kill -INT "$DUMMY_ROS_PID"
else
  printf '%s\n' '未输入有效 PID，未发送信号'
fi
停止进程不等于确认机械臂失能。正常释放卡住或反馈中断时，先支撑机械臂、保留日志，按现场情况处理；不能用进程消失来代替设备确认。

5.3 刷新缓存，并确认本域已无节点

Bash · 复制后在终端运行 
export ROS_DOMAIN_ID=83
ros2 daemon stop
ros2 node list --no-daemon --spin-time 2

ros2 daemon stop 只停止本域命令行工具的发现缓存服务，不会关闭业务节点，也不会使能或失能机械臂。最后一条命令绕过缓存进行发现；无输出表示本次发现未看到域83中的节点。结合上一步的实际进程检查判断是否清理完毕，其他域或尚未发现的节点不在此结论内。

“节点重名”警告不等于启动了同样数量的进程：一个进程可以创建多个 ROS 节点。判断是否多开应查看实际 PID、PGID 和启动命令；不要根据节点名数量直接结束进程。

5.4 在终端手动重开

仍在已经完成第1节环境加载的 Bash 中时，运行第2节启动命令即可。若换了终端，先重新执行第1节；为每轮报告生成新目录。连接保持只读，再由操作者确认恢复控制或标定。

Bash · 复制后在终端运行 
ros2 launch dummy_bringup manual_joint_panel.launch.py \
  backend:=ros \
  sdk_prefix:="$DPSDK_HOST_SDK_PREFIX" \
  config:="$HOME/.local/share/dummy_ros/manual_panel/current/panel-config.json" \
  moveit:=true \
  auto_calibrate_and_test:=false \
  operator_confirmed_double_limits:=false \
  report:="$ROS_WS/dummy_reports/manual-$(date +%Y%m%d-%H%M%S)"
释放状态和设备重启的含义

RELEASE_PENDING / RELEASE_UNCONFIRMED 表示尚未取得释放确认，不能把按钮文字、进程退出或机械臂暂时不动当作释放完成。EVIDENCE_INCOMPLETE;RELEASED_IDLE 可表示物理释放已确认，但本轮证据不完整的失败仍然保留。

如果本次启动因已有owner被预检拒绝、尚未创建自己的ROS控制进程，点击停止只撤销本界面意图，不向外部owner发送D10；可重新连接重试发现。原释放超时后再次点击、且没有待回执时，控件不应一直busy。控件恢复可点击并不表示设备已释放，仍需核实际控制链状态。

REF 重启导致原 USB 消失时，旧进程应退出后再建立只读连接；重连不会自动恢复运动。保持同 boot 且 reference 仍有效时通常无需重烧或重新双限位标定。

查看进程和日志，单独关闭 MoveIt

ROS canceled中的status: 5表示Action已取消。向上查看本轮moveit-events.jsonl中的AUTO_TEST_ABORTED.reason或面板的第一条退出原因，才能判断是人工中断、反馈/身份异常还是规划错误；取消终态本身不等于设备故障，也不代表测试通过。MANUAL_CONTROL_READY表示控制链仍可受理手动控制。

Bash · 复制后在终端运行 
pgrep -af '[r]os2 launch dummy_bringup|[m]anual_joint_panel.py|[d]evice_action_gate|[m]anual_ros_baseline_node|[m]oveit_ros_move_group/move_group|[r]viz2'
ros2 node list
ros2 service list | rg 'device_action_gate|compute_ik|plan_kinematic_path'

正常整轮退出优先使用启动终端的 Ctrl+C。如只需结束规划器，先停止并确认机械臂失能，再查询其 PID，输入要关闭的进程号：

Bash · 复制后在终端运行 
pgrep -af '[m]oveit_ros_move_group/move_group'
read -r -p '输入要关闭的 move_group PID: ' MOVEIT_PID
kill -INT "$MOVEIT_PID"

只结束 MoveIt 不等于机械臂失能。不要用全局 pkill python 或 kill -9 代替正常释放；单个节点退出后，若需完整规划能力，请正常退出原 launch 再启动一轮。

Bash · 复制后在终端运行 
# 查看本轮面板报告与最近 ROS 日志
ls -lt "$ROS_WS/dummy_reports"
ls -lt "$HOME/.ros/log"
# 查看最近报告中的事件（将路径换成本轮实际目录）
# tail -n 30 /本轮报告目录/moveit-events.jsonl

保留报错原文、时间、本轮报告目录与连接目标。圆柱碰撞导致候选路径被拒绝属于有效拦截；若整轮自动测试因此退出，需进一步区分规划失败、真实设备故障和面板反馈处理问题。

首次安装或主动重建

已有可用安装时不用每次构建。新电脑先准备 ROS Jazzy、项目依赖、已导出的 PIC SDK 和匹配的部署配置，再从 ROS 仓库根目录运行：

Bash · 复制后在终端运行 
export DPSDK_ROOT="$ROS_WS/../dpsdk"
export DPSDK_HOST_SDK_PREFIX="/实际/SDK/安装目录"
cd "$ROS_WS"
bash scripts/build_manual_panel.sh
# 构建完成后重新执行第1节环境加载，再使用第2节启动命令

构建脚本只构建需要的接口、描述、规划、控制与面板包，不连接或使能设备。更新源码后使用针对性构建/安装；更换固件部署需要重新核验完整部署身份，不要仅替换某个哈希。

开发者看哪里

  • applications/dummy_ref_control/dummy_sdk/：Native 与 ROS 共用 SDK 的接口、实现和 CMake 导出；公共 <dummy_ref/...> include 用法保持一致。
  • applications/dummy_ref_control/host/：Native CLI 入口与命令行适配。
  • src/dummy_bringup/launch/manual_joint_panel.launch.py：ROS 面板公开启动入口。
  • src/dummy_bringup/scripts/manual_panel_ros_backend.py：面板 ROS 传输适配；设备准入与最终完成由控制链确认。
  • ~/.local/share/dummy_ros/manual_panel/current/panel-config.json：当前本机部署入口，不能从历史报告目录随意拼装。

本页面内含样式和复制功能，复制 HTML 即可离线阅读；命令引用的 SDK、工作区和部署配置属于实际运行环境，不作为网页资源下载。
